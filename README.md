## Запуск клиента

Требуется Node.js 24 LTS версии 24.12 или новее.

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

Открыть адрес из терминала, обычно http://localhost:5173.

В приложении три экрана: список заявок, создание заявки и вход. Список и форма обращаются к API-модулю. При `npm run dev` учебный HTTP mock отвечает на `/__mock/api/support-tickets`; данные находятся в памяти dev-сервера и сбрасываются при его перезапуске. Обновление вкладки повторно загружает этот список. Форма входа демонстрационная, авторизация не выполняется.

В `.env` задаётся `VITE_API_BASE_URL=http://localhost:5000`. Этот файл исключён из Git, в репозитории хранится `.env.example`. После изменения переменной нужно перезапустить Vite. Выбор mock или реального `fetch` находится только в `src/api/tickets.js`. В сборке без dev-сервера используется прямой JavaScript mock; его данные сбрасываются при обновлении вкладки.

Для проверки в режиме разработки:

| Адрес | Проверка |
|-------|----------|
| `/` | Загрузка и список заявок |
| `/?mock=empty` | Пустой список |
| `/?mock=500` | Ошибка загрузки |
| `/new?mock=500` | Отказ создания с HTTP 500 |
| `/new?api=real` | Реальный запрос к порту 5000; при выключенном API — отсутствие связи |
| `/dev/api-check.html` | Вызов API напрямую: успешное создание и HTTP 400 для темы `abc` |

Учебные параметры учитываются API-модулем при загрузке страницы только в режиме разработки. Для возврата к обычному режиму откройте `/` без параметров с обновлением страницы. На проверочной странице откройте F12 → Network → Fetch/XHR, затем нажмите «Создать корректную заявку» и «Отправить тему abc»: появятся POST со статусами `201` и `400`. Обработчик mock подключён только к dev-серверу; учебная страница не включается в production-сборку.

Проверка сборки из папки `frontend`:

```bash
npm run build
```
