# Известные ограничения и открытые проверки

## Результат проверки

В проверенных сценариях создания, назначения, начала работы, закрытия, отмены и фильтрации блокирующих дефектов не обнаружено. [Критерии приёмки](acceptance-check.md), [отчёт](reports/lab-12.md).

При проверке исправлены два дефекта:

- Явно пустой `role` мог обрабатываться как Engineer по умолчанию. Теперь пустое, пробельное, повторённое или неподдерживаемое значение возвращает 400; отсутствие параметра выбирает Engineer.
- Поздний ответ списка после ухода со страницы мог заменить данные нового экрана. Обработчики учитывают завершение жизненного цикла компонента; старые GET/PATCH и ответ создания не меняют новый экран и не вызывают запоздалый переход. Добавлены регрессионные тесты.

## Ограничения

| Ограничение | Практическое значение |
|---|---|
| Реестр загружает все доступные записи без пагинации | Фильтр уменьшает результат, но отдельные страницы списка пока не предусмотрены |
| JWT и учебные учётки рассчитаны на локальный учебный контур | Токен хранится в sessionStorage вкладки; после истечения 30 минут требуется новый вход |
