## Одна запись в интерфейсе, HTTP и SQL

Фактические запросы браузера, их тела, коды и ответы сохранены в [browser-http.json](reports/evidence/lab-12/browser-http.json). Для ответов списков выделена заявка 70 и указано общее количество строк; ответы POST/PATCH сохранены полностью. Авторизация и токены в журнал не включены.

Прямой запрос к PostgreSQL:

```sql
SELECT id, number, title, status, assignee_user_id
FROM support_tickets
WHERE id = 70;
```

Результат: `70 / SUP-2026-0068`, InProgress, исполнитель 2. [SQL до остановки API](reports/evidence/lab-12/database-before-restart.json), [SQL после запуска](reports/evidence/lab-12/database-after-restart.json).

После остановки API его процесс сменился с 11488 на 20352; в промежутке `/health` был недоступен. После запуска и обновления браузера все поля заявки совпали. PostgreSQL продолжал работать; схема, seed и миграции повторно не выполнялись. [Сводка](reports/evidence/lab-12/browser-summary.json), [экран после перезапуска](reports/images/lab-12/after-restart.jpg).

## Отказные сценарии

В [HTTP-проверках](reports/evidence/lab-12/http-summary.json) проверены гостевой доступ 401, недостаточные права и чужая заявка 403, неверные поля и ссылки 400, недопустимое состояние 409. Отказы сохраняют прежние данные. Проверены терминальные состояния, отдельные PATCH и фильтры без расширения видимости инженера.

Порядок повторения полного сценария находится в [README](../README.md#проверка-сквозного-сценария).
