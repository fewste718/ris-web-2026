# Матрица ролей

Система управления заявками технической поддержки ООО «МобиусТех». Роли и правила соответствуют [требованиям](lab-01-requirements.md) и [API-контракту](api-contract.md).

Гость — пользователь без действительного входа, а не отдельная роль в таблице `users`.

| Действие | Диспетчер | Инженер | Гость |
|---|---|---|---|
| `GET /api/support-tickets` | Общий реестр | Только назначенные ему заявки | 401 |
| `GET /api/support-tickets/{id}` | Любая существующая заявка | Своя; чужая → 403 | 401 |
| `POST /api/support-tickets` | Создать → 201 | 403 | 401 |
| `PATCH /api/support-tickets/{id}/assignee` | Назначить/переназначить инженера при New | 403, включая назначение себя | 401 |
| `PATCH /api/support-tickets/{id}/status`, InProgress | 403 | Только своя New → InProgress | 401 |
| Тот же маршрут, Closed | 403 | Только своя InProgress → Closed | 401 |
| Тот же маршрут, Cancelled | New или InProgress → Cancelled | 403, включая свою заявку | 401 |
| Изменить статус чужой заявки | Отмена по правилу выше | 403 | 401 |
| `GET /api/auth/me` | Свой профиль | Свой профиль | 401 |

Дополнительные условия:

- Фильтр `?status=...` не расширяет доступ инженера.
- Автор, номер и время создания определяются сервером. Подмена `X-User-Id` не меняет сотрудника.
- Для разрешённого роли действия неверное состояние заявки даёт 409: например, своя New → Closed, назначение после начала работы или повторная отмена Cancelled.
- Неизвестный код статуса, неверные поля и ссылки дают 400; отсутствующая заявка — 404.
- Closed и Cancelled окончательны. Отмена сохраняет запись и исполнителя.
- Назначение и статус меняются отдельными запросами. DELETE и общего PATCH нет.

## Учебные пользователи и вход

`dispatcher1` — диспетчер (ID 1), `engineer1` и `engineer2` — инженеры (ID 2 и 3). Учебные пароли и порядок запуска приведены в [README](../README.md#вход-и-права). В БД хранятся только библиотечные хеши с солью.

Используется один способ входа: JWT в `Authorization`. Нет токена, неверная подпись или истёкший срок — 401. Пользователь с действительным входом без разрешения на действие или объект получает 403. Проверки выполняются сервером независимо от кнопок Vue.
